# 02 — desktop-shell — Workspace loading at startup + sample asset + smoke

## Goal

Wire `IWorkspaceStore` into `MainWindowViewModel` and `App.OnStartup` so that launching the desktop with a workspace path on the command line loads it before the window renders. Ship `examples/sample.bws` as a runtime asset of the Desktop project so `dotnet run -- examples/sample.bws` produces a populated Overview tab. **The "no path provided" branch keeps the empty-shell placeholder** — the proper welcome UX is `desktop-startup-and-open-workspace`.

`desktop` (WPF / C#).

## What to Build

### `MainWindowViewModel.cs` — gain `IWorkspaceStore` and `InitializeAsync`

- Constructor signature gains `IWorkspaceStore store` (alongside the existing `OverviewViewModel` from step 01).
- New method:
  ```csharp
  public async Task InitializeAsync(string? workspacePath, CancellationToken ct = default)
  {
      if (string.IsNullOrEmpty(workspacePath))
      {
          Workspace = null;       // empty-shell mode
          return;
      }
      Workspace = await _store.LoadAsync(workspacePath, ct);
  }
  ```
- Setter for `Workspace` (or its `OnWorkspaceChanged` partial method generated by `[ObservableProperty]`) calls `Overview.Show(value)` — already wired in step 01; verify still correct.
- No exception handling here — `LoadAsync` already throws clear `InvalidDataException` on bad workspaces. App-level error path (showing user a dialog) belongs to `desktop-startup-and-open-workspace`. For step 02, an exception bubbling out of `OnStartup` is acceptable and expected — manual test verifies the happy path only.

### `App.xaml.cs` — pass CLI args to `InitializeAsync`

- `OnStartup` becomes:
  ```csharp
  protected override async void OnStartup(StartupEventArgs e)
  {
      _host = DesktopHost.CreateApplicationBuilder(e.Args).Build();
      await _host.StartAsync();

      var vm = _host.Services.GetRequiredService<MainWindowViewModel>();
      var workspacePath = e.Args.FirstOrDefault();
      await vm.InitializeAsync(workspacePath);

      var window = _host.Services.GetRequiredService<MainWindow>();
      window.DataContext = vm;
      window.Show();

      base.OnStartup(e);
  }
  ```
- Note ordering: `InitializeAsync` runs **before** `Show()` so the window paints with content already populated (no flicker, no async-update on UI thread mid-render).
- `OnExit` unchanged.

### `ParameterizationExtractor.Desktop.csproj` — copy `examples/sample.bws` to output

```xml
<ItemGroup>
  <None Include="..\examples\sample.bws">
    <CopyToOutputDirectory>PreserveNewest</CopyToOutputDirectory>
    <Link>Examples\sample.bws</Link>
  </None>
</ItemGroup>
```

This mirrors the Tests project's setup. Result: `bin/Debug/net10.0-windows/Examples/sample.bws` is available at runtime, so a developer can `dotnet run -- Examples\sample.bws` from the build output dir, or `dotnet run -- ..\..\..\..\examples\sample.bws` from project source.
