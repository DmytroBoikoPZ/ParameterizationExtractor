# Desktop Extras Tab — Standalone Tables

## Goal

Replace the Extras tab placeholder with the **standalone-tables half of M7**: a list editor for `TablesToProcess` entries that are NOT reachable from the seed via FKs (lookup tables, reference data, anything outside the FK graph). Reuses `Controls/TablePicker/` for adding tables and extracts the inlined `WhereFilterEditor` + `StrategyPicker` from `desktop-graph-tab`'s inspector into proper reusable controls — closing the second-consumer note that graph-tab left behind.

The pre/post-extraction script half of M7 is **deferred** to two follow-up features: `engine-pre-post-scripts` (engine model + JSON + T4 emission) and `desktop-extras-scripts` (UI editor). Splitting lets us ship value now without blocking on engine work.

## Scope

- **In scope:**
  - **Reusable controls** — extract `Controls/WhereFilterEditor/` (single-line `SqlEditor` wrapper with placeholder + label) and `Controls/StrategyPicker/` (the four-radio chooser currently inlined in `NodeInspectorView`). Refactor `NodeInspectorView` to use them — no behaviour change. Components.md marks both as proper UserControls.
  - **`ExtrasViewModel`** (Singleton, mirrors `SeedViewModel`/`GraphViewModel` pattern) — exposes `ObservableCollection<StandaloneTableViewModel> StandaloneTables` filtered to `TablesToProcess` entries whose `(Schema, Name)` is **not** in `GraphViewModel.AllNodes`. Subscribes to `Seed.SelectedScript` for anchor + `GraphViewModel.AllNodes` `INotifyCollectionChanged` for re-filter on graph hydrate. Add/Remove commands; per-row Edit opens an inline expander or row-detail flyout. Save-on-change debounced (mirrors `NodeInspectorViewModel` pattern).
  - **`StandaloneTableViewModel`** (Transient, one per row) — wraps a `TableToExtract` reference; observable Schema, Name, StrategyChip, Where, Excluded; reuses the same Strategy/Where save-on-change wiring as `NodeInspectorViewModel`.
  - **`ExtrasView.xaml`** — DataGrid (or ListBox + DataTemplate) with columns `Table` / `Strategy` / `Where` / `[Edit]`. "+ Add table" button opens a TablePicker dialog (reuses `Controls/TablePicker/`). Edit row → expanded inline view with `WhereFilterEditor` + `StrategyPicker` + Excluded checkbox + Remove button. Empty state shows hint when no standalone tables exist.
  - **`IDialogService.ShowAddStandaloneTableDialogAsync`** — a small dialog wrapping `TablePicker` that returns the selected `TableRef?`. Reused if other features need a table-pick dialog.
  - **MainWindow wire-up** — `MainWindowViewModel` ctor gains `ExtrasViewModel` param + property; the Extras tab's `<TabItem>` content swaps from placeholder text to `<extras:ExtrasView DataContext="{Binding Extras}"/>`. `ExtrasViewModel.Bind(SaveWorkspaceAsync)` mirrors Seed/Graph wiring. `ExtrasViewModel.Hydrate(workspace, plaintextPassword)` called from `OnWorkspaceChanged`. Anchor sync: `Seed.PropertyChanged` for `SelectedScript` already routes to Graph; extend the same handler to route to Extras.
  - **Tests** — `ExtrasViewModelTests` (filter excludes FK-reachable tables; Add creates new TableToExtract entry; Remove deletes from TablesToProcess + saves; Edit propagates to engine model; anchor change re-loads from new script; graph hydration re-filters list). `StandaloneTableViewModelTests` (Strategy/Where/Excluded mutate engine in-place + save-on-change debounce; mirror NodeInspectorViewModelTests pattern). DI smoke in `HostCompositionTests`.
  - **Cross-doc updates** — M7 mockup status → "implemented (standalone-tables half; scripts half deferred)"; components.md marks `WhereFilterEditor` + `StrategyPicker` as proper UserControls; roadmap moves `desktop-extras-tab` to Completed and promotes `engine-pre-post-scripts` to Proposed Next.

- **Out of scope:**
  - **Pre/post-extraction scripts** — no engine support today. Scaffolded as `engine-pre-post-scripts` (engine track) + `desktop-extras-scripts` (desktop track). The Extras tab is structured so the script section can be slotted in below the standalone-tables list without rework.
  - **`Standalone` flag on `TableToExtract`** — the engine model doesn't gain a new field. Standalone-vs-reachable is a *view*, computed from the FK graph at runtime. If an operator adds a "lookup" table that turns out to be FK-connected later, it migrates between tabs — that's the desired behaviour, not a bug.
  - **Multi-script bulk operations** — Extras edits the current anchored script's `TablesToProcess` only, mirroring Graph tab's single-script convention.
  - **External script files / "Add from file…"** — out of scope (feature is standalone tables only this round).
  - **Manual smoke walk-through** — operator-driven per the WPF recipe; UI changes aren't unit-tested. VM tests cover behaviour; XAML wiring is traceable to bound properties.

- **Dependencies:**
  - [`desktop-graph-tab`](./archive/desktop-graph-tab-checklist.md) — provides `GraphViewModel.AllNodes` (used to compute the filter), the `NodeInspectorViewModel` save-on-change debounce pattern, and the inlined `StrategyPicker`/`WhereFilterEditor` to be extracted.
  - [`desktop-seed-tab`](./archive/desktop-seed-tab-checklist.md) — provides `Controls/TablePicker/`, `IUiDispatcher`, and the `Seed.SelectedScript` anchor signal.
  - Mockup: [M7 — Extras](../docs/design/desktop-ui/07-extras.md) (standalone-tables half only this round).
  - Components: [TablePicker](../docs/design/desktop-ui/components.md#tablepicker), [StrategyPicker](../docs/design/desktop-ui/components.md#strategypicker), [WhereFilterEditor](../docs/design/desktop-ui/components.md#wherefiltereditor).
